# GigaChat в OpenCode 2.x

OpenCode 2 не пропускает запросы провайдеров через `globalThis.fetch`, поэтому перехватчик из V1 там не работает.
Этот файл описывает сборку V2: плагин сам поднимает локальный HTTP-эндпоинт и регистрирует провайдера `gigachat`, который на него указывает.

Инструкции для OpenCode 1.x остаются в [README](../README.md) и [CONFIGURATION](CONFIGURATION.md).

## Требования

* OpenCode 2.x. Проверено на `2.1.4`.
* Готовый файл `dist/gigachat-plugin-v2.js`.

## Установка

1. Закройте OpenCode.
2. Скопируйте файл в папку плагинов:

   ```bash
   cp dist/gigachat-plugin-v2.js "$HOME/.config/opencode/plugins/gigachat-plugin-v2.js"
   ```

   Если в папке остался V1-файл `gigachat-plugin.js`, удалите его: два экземпляра плагина будут бороться за один порт.

3. Объявите провайдера в `~/.config/opencode/opencode.json`, чтобы появилась интеграция с методами входа:

   ```json
   {
     "providers": {
       "gigachat": {
         "name": "GigaChat (Sberbank)",
         "env": ["GIGACHAT_CREDENTIALS"],
         "package": "@opencode/ai/providers/openai-compatible",
         "settings": { "baseURL": "http://127.0.0.1:45731/v1" },
         "models": {
           "GigaChat-2": {
             "name": "GigaChat 2 (Text)",
             "limit": { "context": 128000, "output": 4096 },
             "capabilities": { "tools": true, "input": ["text"], "output": ["text"] }
           },
           "GigaChat-2-Pro": {
             "name": "GigaChat 2 Pro (Multimodal)",
             "limit": { "context": 128000, "output": 8192 },
             "capabilities": { "tools": true, "input": ["text", "image", "audio"], "output": ["text"] }
           },
           "GigaChat-2-Max": {
             "name": "GigaChat 2 Max (Reasoning)",
             "limit": { "context": 128000, "output": 8192 },
             "capabilities": { "tools": true, "input": ["text", "image", "audio"], "output": ["text"] }
           },
           "GigaChat-3-Lightning": {
             "name": "GigaChat 3 Lightning (Fast)",
             "limit": { "context": 128000, "output": 8192 },
             "capabilities": { "tools": true, "input": ["text"], "output": ["text"] }
           },
           "GigaChat-3-Pro": {
             "name": "GigaChat 3 Pro (Multimodal)",
             "limit": { "context": 128000, "output": 8192 },
             "capabilities": { "tools": true, "input": ["text", "image", "audio"], "output": ["text"] }
           },
           "GigaChat-3-Ultra": {
             "name": "GigaChat 3 Ultra (Flagship)",
             "limit": { "context": 128000, "output": 8192 },
             "capabilities": { "tools": true, "input": ["text", "image", "audio"], "output": ["text"] }
           }
         }
       }
     }
   }
   ```

   Порт `45731` — это адрес локального эндпоинта плагина. Значение по умолчанию можно изменить переменной `GIGACHAT_ENDPOINT_PORT`, но тогда его нужно поправить и здесь.

4. Удалите из `opencode.json` старую запись провайдера `GigaChat (Sberbank)` из раздела `provider`, если она осталась.
5. Запустите OpenCode и выберите модель `gigachat/GigaChat-2`.

Перед первым запросом задайте ключ: см. [Учётные данные](#учётные-данные).

### Без объявления провайдера

Плагин умеет работать и сам: если записи `gigachat` в конфигурации нет, он добавляет провайдера сам, но с произвольным портом.
В этом режиме интеграции не существует, поэтому `/connect` и `opencode auth login` недоступны, а ключ читается только из переменных окружения.

### Почему запись провайдера должна быть объявлена

Для провайдера, объявленного в файле конфигурации, `editor.update` и `editor.remove` из трансформа плагина не сохраняются: OpenCode применяет конфигурацию после трансформов. Проверено на `2.1.4`.
По той же причине плагин не может и создать интеграцию: для провайдера, добавленного плагином, интеграция не появляется. Объявление провайдера в конфигурации — единственный способ получить методы входа.

## Модели

Плагин объявляет тот же список, что и V1, плюс поколение GigaChat 3, которое API возвращает в `GET /v1/models`.
Более старые идентификаторы из списка убраны: Сбер их больше не обслуживает.
`GigaChat-2-Lite` в список не входит: API не возвращает его как отдельную модель, а запрос с этим именем плагин заменяет на `GigaChat-2`.

| Модель | Контекст | Вывод | Ввод |
| --- | --- | --- | --- |
| `GigaChat-2` | 128000 | 4096 | текст |
| `GigaChat-2-Pro` | 128000 | 8192 | текст, изображение, аудио |
| `GigaChat-2-Max` | 128000 | 8192 | текст, изображение, аудио |
| `GigaChat-3-Lightning` | 128000 | 8192 | текст |
| `GigaChat-3-Pro` | 128000 | 8192 | текст, изображение, аудио |
| `GigaChat-3-Ultra` | 128000 | 8192 | текст, изображение, аудио |

Возможности проверены на живом API:

* инструменты работают у всех шести моделей;
* изображения принимают `GigaChat-2-Pro`, `GigaChat-2-Max`, `GigaChat-3-Pro`, `GigaChat-3-Ultra`;
* аудио принимают те же четыре модели; `GigaChat-2` и `GigaChat-3-Lightning` отвечают `422 Model does not support audio`;
* `GigaChat-3-Lightning` на изображение отвечает ошибкой 500, поэтому объявлена только текстовая модальность.

Контекст 128k указан для всех моделей сознательно: Сбер документирует 128k для GigaChat 2 и GigaChat 3 Ultra, а лимиты 3-Pro и 3-Lightning в API не опубликованы.
Заниженное окно безопасно — OpenCode просто раньше выполняет компакцию контекста.

`GigaChat-3-Ultra` по документации Сбера доступна физлицам в freemium-режиме; на платных тарифах доступа к ней пока нет, но список моделей в OpenCode от тарифа не зависит.

Ссылка на модель в сессии выглядит как `gigachat/GigaChat-3-Ultra`.
Имя `GigaChat-2-Lite` плагин по-прежнему заменяет на `GigaChat-2` перед запросом к API, как и в V1, но моделью в списке не показывает.

## Учётные данные

| Переменная | Назначение |
| --- | --- |
| `GIGACHAT_CREDENTIALS` | Ключ `Base64(Client_ID:Client_Secret)`; несколько ключей разделяются `;`, запятой или переводом строки |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS`, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP` |
| `GIGACHAT_VERIFY_SSL` | `false` отключает проверку TLS |
| `GIGACHAT_CA_BUNDLE_FILE` | Путь к своему PEM-бандлу сертификатов |
| `GIGACHAT_API_URL` | Базовый адрес GigaChat API вместо `https://api.giga.chat/v1` |
| `GIGACHAT_OAUTH_URL` | Адрес OAuth вместо `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`; нужен для корпоративного прокси |
| `GIGACHAT_ENDPOINT_PORT` | Порт локального эндпоинта; должен совпадать с `baseURL` объявленного провайдера |
| `GIGACHAT_MAX_CONCURRENCY` | Сколько запросов на один аккаунт выполнять одновременно; по умолчанию `1` |

`GIGACHAT_API_URL` заменяет прежний способ с корпоративным прокси: в V1 адрес указывался в `baseURL` провайдера, но в V2 поле `baseURL` занято локальным эндпоинтом плагина.

Вход через `/connect` (`opencode auth login gigachat`) сохраняет ключ в базе сервиса.
Плагин читает его перед каждым запросом, поэтому вход действует без перезапуска.

Порядок источников ключа:

1. Сохранённое подключение в OpenCode (`/connect`, `opencode auth login`).
2. Переменные окружения.
3. Поля `credentials` и `scope` из прежней записи провайдера `GigaChat (Sberbank)`, если она ещё осталась в конфигурации.

Ограничение входа по ключу: OpenCode показывает для такого провайдера свою стандартную форму ввода ключа, а объявленная плагином форма с выбором scope не сохраняется — платформа подставляет свой метод `key`.
Поэтому scope задаётся переменной `GIGACHAT_SCOPE` (по умолчанию `GIGACHAT_API_PERS`), в том числе при входе через `/connect`.

Для фонового сервиса переменные задаются через `opencode service set env`.
Команда перезапускает сервис.

```bash
opencode service set env GIGACHAT_CREDENTIALS "<Base64(Client_ID:Client_Secret)>"
opencode service set env GIGACHAT_SCOPE GIGACHAT_API_PERS
```

Так как `GIGACHAT_CREDENTIALS` указан в поле `env` объявленного провайдера, переменная видна в `opencode auth list` как подключение типа `environment`.
Проверить сохранённые подключения можно там же.

## Несколько аккаунтов

В V1 поддерживался один ключ. В V2 можно перечислить несколько, и плагин будет ротировать их при ошибках квоты.

* Переменная `GIGACHAT_CREDENTIALS` принимает список: `key1;key2` или каждый ключ с новой строки. Scope у всех будет один — из `GIGACHAT_SCOPE`.
* В объявленном провайдере можно задать аккаунты с разными scope:

  ```json
  "accounts": [
    { "credentials": "<key1>", "scope": "GIGACHAT_API_PERS" },
    { "credentials": "<key2>", "scope": "GIGACHAT_API_B2B" }
  ]
  ```

Плагин начинает с первого аккаунта. На `401`, `403` и `429` он помечает текущий аккаунт остывающим на минуту, переключается на следующий и повторяет запрос один раз.
Токен кэшируется отдельно для каждого аккаунта, поэтому возврат к первому не требует нового OAuth.
Если остывают все, плагин продолжает цикл, а не роняет запрос.

`402 Payment Required` не включает ротацию: это ограничение тарифа на конкретную операцию, а не исчерпание квоты аккаунта.

## Одновременные запросы

GigaChat принимает только один запрос на аккаунт одновременно: второй сразу получает `429`, даже если первый ещё выполняется.
OpenCode при первом сообщении новой сессии почти одновременно отправляет запрос на заголовок сессии и основной запрос, поэтому без очереди первый ответ мог падать с `429`.

Плагин ставит запросы к GigaChat в очередь на уровне аккаунта: chat completions, embeddings и `gigachat_generate_image`.
По умолчанию одновременно выполняется один запрос на аккаунт.
Для платных тарифов лимит можно поднять переменной `GIGACHAT_MAX_CONCURRENCY`.

Если `429` всё же пришёл (например, тот же ключ использует другой процесс), плагин один раз повторяет запрос: сначала пробует следующий аккаунт, а если его нет — ждёт секунду.
Очередь не мешает ротации: запросы ждут свободный слот, а ошибки `401`, `403` и `429` по-прежнему переключают аккаунт.

## Генерация изображений

Плагин регистрирует инструмент `gigachat_generate_image`: он вызывает встроенную функцию GigaChat `text2image`, скачивает готовый файл через `/files/{id}/content` и сохраняет его на диск.

| Параметр | Обязательный | Назначение |
| --- | --- | --- |
| `prompt` | да | Что нарисовать |
| `path` | нет | Куда сохранить `.jpg`; относительный путь считается от каталога сессии |
| `model` | нет | Модель GigaChat; по умолчанию `GigaChat-2-Max` |

Инструмент возвращает путь к файлу и идентификатор файла в GigaChat. Если тариф не включает генерацию, API отвечает `402`, и инструмент возвращает эту ошибку с пояснением.

## Рассуждения

`reasoning_effort` и `thinking.budget_tokens` работают в двух режимах:

* **Без инструментов** плагин передаёт `reasoning_effort` в GigaChat нативно. Цепочка рассуждений приходит в `reasoning_content` и передаётся клиенту как есть.
* **С инструментами** нативный флаг использовать нельзя: GigaChat отвечает `500` на запрос, где одновременно есть `functions` и `reasoning_effort`. Поэтому плагин добавляет системную инструкцию с просьбой рассуждать пошагово, а флаг не отправляет. Агентские сессии OpenCode всегда передают инструменты, так что на практике это основной путь.

## Аудио и вложения

Клиент может прислать аудио частью `input_audio` (`{ data, format }`). Плагин загружает её в `/files` как `purpose=general` и передаёт идентификатор в `attachments` — так же, как изображения.

Аудио принимают `GigaChat-2-Pro`, `GigaChat-2-Max`, `GigaChat-3-Pro` и `GigaChat-3-Ultra`; остальные модели отвечают `422 Model does not support audio`.

## Ошибки

Ответ об ошибке сохраняет статус GigaChat и дополняется пояснением:

| Статус | Пояснение |
| --- | --- |
| `401` | токен отклонён, проверьте ключ |
| `402` | тариф не включает операцию |
| `403` | квота или биллинг аккаунта исчерпаны |
| `429` | превышен лимит запросов |

Причина от сервера показывается рядом с кодом, если GigaChat её прислал.

## Диагностика

У плагина V2 нет доступа к `client.app.log`, который использовался в V1.
Сообщения выводятся в консоль только при `GIGACHAT_DEBUG=true`:

```bash
GIGACHAT_DEBUG=true opencode run --standalone --print-logs -m gigachat/GigaChat-2 "привет"
```

`--standalone` запускает приватный сервер, поэтому вывод серверных сообщений виден в терминале.

## Ограничения V2

* Релизная проверка пока покрывает только файл V1 (`npm run test:release`).
  Тесты транспорта V2 находятся в `src/v2/endpoint.test.ts`.
* Полный прогон с реальным ключом Сбера и вход через `/connect` ещё не выполнялись.
* Проверка размера текста осталась: плагин подписывается на хук `prompt`.

## Отличия от V1

| Область | V1 | V2 |
| --- | --- | --- |
| Точка перехвата | Подмена `globalThis.fetch` | Локальный HTTP-эндпоинт плагина |
| Провайдер | Объявляет пользователь в `opencode.json` | Объявляет плагин (`gigachat`) |
| Адрес провайдера | Виртуальный `https://api.gigachat.local/v1` | `http://127.0.0.1:<порт>/v1` |
| Выбор запросов | По хосту и заголовку `x-opencode-provider-marker` | По идентификатору провайдера и пути эндпоинта |
| Ключ | Хук `auth`, опции провайдера, переменные | Переменные окружения (интеграция — далее) |
| Логи | `client.app.log` | Консоль при `GIGACHAT_DEBUG=true` |
| Преобразование форматов | `translation`, `messages`, `tools`, `responses`, `stream`, `attachments` | Тот же код без изменений |
